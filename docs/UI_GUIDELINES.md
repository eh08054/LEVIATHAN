# UI 디자인 가이드라인 (요약)

원본: `EVA_UI_Design_Guidelines_for_Claude_Code.pdf` (2026-11-16, 사용자가 GPT로 참고 이미지의 규칙을 정리해 받은 문서). 이 프로젝트에 맞춘 적용 결정은 아래 '프로젝트 적용'에 적는다.

## 핵심 방향
- 도시의 분위기는 배경이 담당하고, 정보의 전달은 UI가 담당한다.
- 화면마다 하나의 핵심 목적을 두고, 중요한 정보부터 눈에 들어오게 만든다.

## 원칙
- **위계:** 핵심 수치·선택 항목·주요 콘텐츠는 크게, 보조 설명은 작고 차분하게.
- **일관성:** 상단 자원 바, 좌측 내비게이션, 패널 제목, 버튼, 그래프, 상태 색상은 모든 화면에서 같은 규칙.
- **절제:** 네온·Glow·강한 테두리는 선택·경고·핵심 요소에만.
- **여백:** 관련 정보는 묶고, 다른 그룹 사이에는 충분한 간격. 많이 채우는 것보다 읽기 쉬운 구성.
- **몰입:** 장식보다 실제 관리 정보와 시스템의 분위기.
- **피할 것:** 모든 패널에 같은 강도의 청록 Glow, 작은 글자·그래프 과다, 모든 화면을 같은 배치로, 배경 조명과 UI 강조의 경쟁, 디자인을 이유로 기능 제거.

## 색상 토큰
| 역할 | HEX |

| 패널 배경 Panel Navy | #192B46 |
| 주요 강조 Neon Cyan | #35C9E8 (선택 상태, 핵심 테두리, 활성 요소) |
| 선택/활성 Electric Blue | #4C8DFF (선택된 탭·버튼·포커스) |
| 긍정 Success Green | #42D6A4 |

- 청록은 제한적으로. 증감 색은 지표의 의미에 따라(증가가 나쁜 지표도 있다). 색만으로 상태를 전달하지 않는다(아이콘·텍스트·+/− 함께). 배경은 어둡게, 텍스트 대비 확보.

## 패널·컴포넌트
- 배경 어두운 남색, 테두리 1px 청회색(강조 패널만 밝게), 모서리 6~10px, 헤더 = 아이콘 + 제목 + 우측 액션/상태, 내부 여백 12~20px, Glow는 선택·경고·중요 액션에만.
- 공통 컴포넌트: PanelFrame, SectionHeader, StatCard, ResourceDisplay, GraphContainer, NavigationButton, NotificationItem, DataRow.
- 글자: 화면 제목 22~26 굵게, 패널 제목 15~18, 본문 13~15, 핵심 숫자 26~36(Rajdhani 등 숫자 폰트, 큰 숫자 + 작은 단위/증감), 영문 라벨 16~20(짧은 섹션명만 대문자).

## 레이아웃
- 16:9, 기준 1920×1080. Top Bar(자원·날짜·시간·배속·저장)와 Side Navigation은 모든 화면에서 같게. Main Content에 가장 넓은 공간. Detail/Right Panel은 필요한 화면에만. Popup Layer는 메인과 구분.
- 화면별 주인공: Overview = 도시 전경 + 핵심 지표 / Policy = 선택한 정책 + 예상 효과·부작용 / Research = 연구 트리 / Citizen = 초상화 + 개인 프로필 / Surveillance = 감시 현황 + 이상 징후 / Settlement = 종합 평가 + 주요 변화.
- **Overview는 다른 메뉴의 축소판이 되지 않는다.** 핵심 지표 3~5개와 요약(진행 중 연구 1건, 주목할 시민 1명, 정책 요약, 최근 알림)만.
- Observation(사회 동향·여론·집단 불만·예측) 과 Surveillance(구역 감시 상태·개별 행동·이상 징후)는 구분한다.

## 작업 원칙
- 구조 분석 → 차이 목록 → 공통 토큰 → Overview를 기준 화면으로 → 공통 컴포넌트 → 나머지 화면 → 해상도·가독성·기능 회귀 확인.
- 기존 로직·이벤트·참조·저장 기능을 깨지 않는다. 없는 기능·데이터를 지어내지 않는다(임시 표시는 구분). 폰트·에셋은 라이선스 확인, 임의 다운로드 금지.

## 완료 체크리스트
- 핵심 정보가 먼저 보이는가 / 과도한 Glow·강조색이 없는가 / 배경 위 텍스트가 읽히는가 / 화면별 핵심 콘텐츠가 충분한 공간을 갖는가 / 색·폰트·패널·버튼 규칙이 일관적인가 / 기존 동작·데이터 연결이 유지되는가 / 목표 해상도에서 잘림·겹침이 없는가 / 실제 데이터와 임시 데이터가 구분되는가.

## 프로젝트 적용
- 이 프로젝트는 UGUI가 아니라 **UI Toolkit**이고 UI를 C#으로 만든다. 프리팹 대신 C# 빌더 함수와 USS 클래스가 공통 컴포넌트 역할을 한다. Inspector 참조는 `OpsScreen`의 `styleSheet`, `seed` 두 개뿐이다.
- 세부 적용 결정은 Dialog.md와 GDD.md에 기록한다.
