# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Unity **6000.6.0f1** project built from the Universal Render Pipeline (URP 17.7) template. There's very little custom content so far: one scene (`Assets/Scenes/SampleScene.unity`, the only scene in Build Settings) and scripts in `Assets/Scripts/`.

## Game

The game is **LEVIATHAN** (GitHub repository `eh08054/LEVIATHAN`, local folder `LEVIATHAN`): the player is the city-running AI of that name, after Hobbes. The city is 섹터 알파 (Sector α), a World Union test city, 2071-2075 (docs/GDD.md). In-game years, names and jobs follow it; the deeper story rewrite is listed in docs/STORY_AUDIT.md. The index AutonomyFelt is shown as 자율성(체감).

Planning docs live in `docs/`. Keep them updated as the conversation goes:
- `docs/Dialog.md`: summary of each planning conversation, newest entry at the bottom.
- `docs/GDD.md`: only decisions that have been agreed on. Leave undecided items as `미정`.
- `docs/ROADMAP.md`: near-term tasks and their status.
- `docs/UI_GUIDELINES.md`: the UI design guideline (summary of the user's EVA guideline PDF) and how it maps onto this UI Toolkit project. Follow it for any UI work.

## Working with the editor

- **UnityMCP** (`com.coplaydev.unity-mcp`, installed from git in `Packages/manifest.json`) is the main way to drive the editor: creating GameObjects, editing scenes, reading the console, running tests. It only connects while the Unity editor is open with the MCP bridge running. If the connection fails, ask the user to start it rather than assuming it isn't set up.
- **Without MCP**, do not edit `.unity` / `.prefab` YAML by hand. Ask the user to start the MCP bridge first. Only edit YAML if the user explicitly approves.
Requirements:
  - Every new asset needs a `.meta` file with a unique GUID.
  - New scene objects need unique `fileID`s.
  - Root Transforms must be added to the `SceneRoots` → `m_Roots` list at the end of the `.unity` file.
  - If the scene is open in the editor, Unity will ask the user to reload it.
- **The editor generates** the `.csproj` and `.sln` files. They're .gitignored, so don't edit them. There's no command-line build or lint step; Unity compiles scripts when they change.
- **Assemblies:**
  - `Assets/Scripts/Ops/` compiles into `Sector.Ops.asmdef` (`noEngineReferences: true`): the current game's logic, plain C# with no `UnityEngine` dependency.
  - The other scripts in `Assets/Scripts/` (UI, MonoBehaviours) compile into `Assembly-CSharp`.
  - The old stimulus/experiment prototype (`Sector.Simulation`, `SectorScreen`, its pixel art and tools) was deleted on 2026-11-19.
- **Tests:**
  - EditMode tests live in `Assets/Tests/EditMode/Ops/` (`Sector.Ops.Tests.asmdef`). They run from the editor's Test Runner or through MCP (`run_tests` with `assembly_names`, then `get_test_job`).
  - The tests use only NUnit, so they can also be checked without Unity. Build a throwaway net8.0 test project in the scratchpad that compiles `Assets/Scripts/Ops/` and the tests with `LangVersion 9.0`, then run `dotnet test`.
  - UI scripts can be compile-checked without the editor too. Build a netstandard2.1 project that references the module DLLs in `C:/Program Files/UnityEditor/6000.6.0f1/Editor/Data/Managed/UnityEngine/` (`UnityEngine.*Module.dll`). Don't also reference the monolithic `UnityEngine.dll`, or every type is ambiguous.

## Conventions and gotchas

- **Input:** `activeInputHandler: 1` means only the new Input System is enabled. Use `UnityEngine.InputSystem` and `Assets/InputSystem_Actions.inputactions`, not legacy `Input.GetKey`/`Input.GetAxis`.
- **Rendering:** URP is set per quality level.
  - The `Mobile` level uses `Assets/Settings/Mobile_RPAsset`; the `PC` level uses `PC_RPAsset`. Each has its own renderer asset.
  - `GraphicsSettings` has no default pipeline.
  - New renderers should use a URP material, such as the package's `Lit.mat` (guid `31321ba15b8f8eb4c954353edc038b1d`). Built-in `Default-Material` renders pink.

- **UI:**
  - The UI is built with UI Toolkit. `SectorUI` in `SampleScene` holds a `UIDocument` (`Assets/UI/SectorPanelSettings.asset`) and `OpsScreen`, which builds every view in C#.
  - `PixelArt.Load(path)` loads and caches `Resources/Art/<path>` (null if missing). `Assets/Editor/PixelArtImporter.cs` imports `Resources/Art/` (point filtering for small pixel art, smooth for anything wider than 160 px) and big paintings outside it.
  - `Sfx` synthesizes its clips at startup. Swap in real audio there.
  - Captures and `ScreenCapture` need the Unity window in front: an unfocused editor stops advancing frames in play mode (`Time.frameCount` stays put). Ask the user to bring Unity forward.
  - Labels inside a `Button` inherit its centered text; give them `-unity-text-align: middle-left` when they should line up on the left (menu items, tabs, option labels).
  - Mark UI state fields on MonoBehaviours `[NonSerialized]` (or check `string.IsNullOrEmpty`): a script reload in play mode serializes private fields and turns null strings into "".
  - The UI font has no `✕`, `✔` or emoji. Use characters it has (`×`, `▶`, `●`) or plain text.
- **Korean text:**
  - The default UI Toolkit font has no Hangul. `Ops.uss` uses `Assets/Fonts/Pretendard/Pretendard-Regular SDF.asset` (OFL, dynamic atlas; SemiBold and Bold assets are linked as weights 600/700).
  - UI Toolkit spaces lines by ascent minus descent, not by `lineHeight`. In every font asset, ascent and descent were widened to add up to 1.25 × point size (112.5 at 90 pt). Redo that if a font asset is ever regenerated, or wrapped lines (and bold titles) will overlap.
  - Use `\n` in UI strings. `StringBuilder.AppendLine` writes `\r\n` on Windows.
  - When patching C# through a Python heredoc in Bash, write `\n` escapes from a script file instead. Inline heredocs have turned `"\\n"` into a real line break inside a string literal (CS1010).
- **MCP in practice:**
  - If the UnityMCP tools are missing from the session but `claude mcp list` shows UnityMCP connected, call the HTTP endpoint through the helpers in `Tools/Unity/` (run from the project root; they are allowed without prompts in `.claude/settings.local.json`): `call.sh <tool> '<json>'`, `exec.sh <file.cs>` (runs C# through `execute_code`), `wait.sh` (until the editor is ready), `capture.sh` (render_ui to `Assets/Screenshots/`).
  - `Tools/Unity/shot.sh <name>` sometimes catches a frame before the UI is drawn (sky and a grey cube); wait a few seconds and shoot again. It takes a 2x game-view screenshot (`manage_camera screenshot`, supersize 2) into `Assets/Screenshots/<name>.png`; use it to check alignment, since `render_ui` captures at the small game-view size.
  - `manage_ui render_ui` in play mode only finishes while the Unity window is focused. It saves PNGs under `Assets/Screenshots/`; delete that folder afterwards.
